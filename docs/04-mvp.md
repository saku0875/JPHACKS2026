## 1. 目的・背景
- 解決したい課題：小学生の理系科目への興味の向上
- 作る理由（なぜ今か）：
  - 日本では理系人材が少なく，また理系学生も少ない．本プロジェクトではその原因を「理系科目に興味を持つ学生が少ない」というアプローチの元，理系科目への興味を持つ学生の増加を目指す
- 成功の定義（MVP の目標）：
  - デモで「撮影 → 囲む → 問い → 予想 → 答え合わせ → 条件変更 → 保存」の動線が最後まで通ること

## 2. 対象ユーザー
- 主な利用者：小学生中心
- 利用シーン：お出かけをしているときや、外で遊んでいるときなど

## 3. スコープ
**やること（In Scope）**
- Must：4章の F-01〜F-15
- Should：4章の F-16〜F-17（Must の次に実装する。F-16 から先に実装する）

**やらないこと（Out of Scope ＝ MVP 以降に回すもの）**
- 位置情報と地図でのアーカイブ表示（どこで問題に答えたのか、その写真・問題・回答を地図上で見られるようにする）
- プロフィールの切り替え画面（兄弟で1台）。データ構造だけは最初から複数プロフィールに対応する
- 「別のもので試す」（LLM に派生の問いを出させる）
- 送信前に顔を自動でぼかす（他人の顔が映っている場合のモザイク処理）
- モデレーション API による画像と生成文のチェック
- 公開する場合の1日の利用回数制限

## 5. 非機能要件
- 性能：囲んでから問いが出るまで60秒以内（タイムアウトと同じ。待ち時間はナビゲーターキャラの豆知識でつなぐ）
- セキュリティ：F-11 のとおり。不適切な内容はプロンプトで制約する。F-14 の公開ではモデレーションがないため、不適切な投稿を消せる手段：【未決】
- 対応環境：スマホの iOS Safari・Android Chrome（最新版）
- その他（可用性・保守性など）：API の利用回数はハッカソン期間中は制限しない

## 10. リスク・未決事項
| 内容 | 影響 | 対応方針・担当 |
|---|---|---|
| Must が15個あり、2日間では多い | MVP の動線が最後まで通らない | 案：F-01〜F-08 の動線を最優先にし、F-12〜F-15 は動線が通ってから着手する |
| 匿名公開にモデレーションがない | 子どもの不適切な写真・個人情報が公開される | 公開は切り抜き画像だけにする。削除手段は【未決】 |
| LLM の応答時間・料金が未実測 | 60秒に収まらない、料金が想定を超える | Hack Day の最初に実測する |
| パスワードリセットがない | パスワードを忘れるとアーカイブに戻れない | ハッカソン期間中は許容する |
